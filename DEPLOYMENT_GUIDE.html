1. Overview & Architecture

The Seasonal Article Detector Agent is an AI-powered agent that automatically classifies articles as seasonal or non-seasonal using historical sales time-series data from SAP CAR/CARAB. It runs on SAP BTP Cloud Foundry and connects to your on-premise HANA database through SAP Cloud Connector.

Primary Goal: Classify articles as SEASONAL or NON_SEASONAL based on historical sales patterns stored in SAP CAR/CARAB (/DMF/TS_PS). Results are written to on-premise Z-tables for downstream consumption.
Optional steps (configured separately): replenishment adjustment workflow and classification notification workflow — these are triggered post-classification and are not required for the core classification to work.

4. Cloud Connector Configuration

SAP Cloud Connector must be installed on a machine inside your corporate network that has direct TCP access to the CAR HANA server on port 30015.

4.1 Install Cloud Connector

  1. Download from SAP Software Downloads → search "Cloud Connector"
  2. Install on a Windows/Linux host in your on-premise network
  3. Access the Cloud Connector Admin UI: https://<host>:8443
  4. Default credentials: Administrator / manage — change immediately

4.2 Connect to BTP Subaccount

  1. In Cloud Connector Admin UI → Connector → Add Subaccount
  2. Enter your BTP subaccount details:
FieldValue
RegionYour BTP subaccount region (e.g. eu10)
SubaccountYour BTP subaccount ID (found in BTP Cockpit → Subaccount Overview)
Display NameAny descriptive name
Login EmailYour BTP user email
PasswordYour BTP password

Click Save. Status should turn green (Connected).

4.3 Add On-Premise HANA System Mapping

  1. In Cloud Connector Admin UI → Cloud To On-Premise → Access Control
  2. Click Add and fill in:
FieldValue
Back-End TypeSAP HANA
ProtocolTCP
Internal HostActual HANA hostname or IP on your network
Internal Port30015
Virtual Hostcar-hana-virtual (this is what you enter in the BTP Destination)
Virtual Port30015
Principal TypeNone
  1. Click Save
  2. Add a Resource: click the new mapping → Resources tab → Add → Path /, check All Sub-Paths
  3. Under State, check that the mapping shows a green checkmark
The Virtual Host value (car-hana-virtual) must match exactly the Host field in the BTP Destination CAR_HANA configured in Step 3.3.

5. On-Premise HANA Database Setup

This section requires a HANA user with schema object creation privileges (typically a DBA or the SYSTEM user). Run the steps below in SAP HANA Studio, DBeaver, or HANA cockpit against the CAR HANA instance.

5.1 Create Custom Tables (run DDL script once)

The DDL script is located in the repository at:

assets/seasonal-detector-cap/db/ddl.sql

Run this script exactly once before first deployment. It creates:

Table NamePurpose
ZSEASONAL_CLASS_RUNOne row per classification run (status, totals, timestamps)
ZSEASONAL_CLASS_RESULTOne row per article/store classification result

How to run:

-- In HANA Studio: Open SQL Console, paste the contents of ddl.sql, execute.
-- In hdbsql:
hdbsql -u SYSTEM -p <password> -n <host>:30015 -I ddl.sql
The script is idempotent-safe if run in a fresh schema. Do not re-run on an existing installation — it will fail with "table already exists".

5.2 Create Technical User & Grant Permissions

Create a dedicated HANA user for the agent. Uncomment and adapt the GRANT statements at the bottom of ddl.sql:

-- Create the technical user (adjust password policy as required)
CREATE USER ZSEASONAL_USER PASSWORD "<strong-password>" NO FORCE_FIRST_PASSWORD_CHANGE;

-- Minimum permissions for reading CAR time-series data
GRANT SELECT ON "/DMF/TS_PS" TO ZSEASONAL_USER;

-- Permissions for writing classification results
GRANT SELECT, INSERT, UPDATE ON "ZSEASONAL_CLASS_RUN"    TO ZSEASONAL_USER;
GRANT SELECT, INSERT         ON "ZSEASONAL_CLASS_RESULT" TO ZSEASONAL_USER;
The /DMF/TS_PS table uses SAP namespace naming. Ensure it exists in the target schema and that your user has SELECT granted on the correct schema. Verify the MANDT (client) value — the code defaults to '100'. If your system uses a different client, set the HANA_MANDT environment variable (see Section 10).

5.3 Verify Table Access

-- Run as ZSEASONAL_USER to verify access
SELECT COUNT(*) FROM "/DMF/TS_PS" WHERE MANDT = '100';
SELECT COUNT(*) FROM "ZSEASONAL_CLASS_RUN";
SELECT COUNT(*) FROM "ZSEASONAL_CLASS_RESULT";

All three queries should return without permission errors.

6. Deploy CAP Backend

The CAP backend (seasonal-detector-cap) proxies all HANA access and exposes a REST API that the agent calls.

6.1 Clone the Repository

git clone <repository-url> seasonal-agent
cd seasonal-agent/assets/seasonal-detector-cap

6.2 Install Dependencies

npm install

6.3 Log In to Cloud Foundry

cf login -a https://api.cf.<region>.hana.ondemand.com
# Enter your email and password when prompted
cf target -o <your-org> -s <your-space>

6.4 Build the MTA Archive

mbt build

This creates a .mtar file in the mta_archives/ directory.

6.5 Deploy to Cloud Foundry

cf deploy mta_archives/seasonal-detector-cap_1.0.0.mtar

The deployment will automatically:

  • Create the seasonal-detector-connectivity service instance (Connectivity, lite)
  • Create the seasonal-detector-destination service instance (Destination, lite)
  • Create the seasonal-detector-xsuaa service instance (XSUAA, application)
  • Deploy the seasonal-detector-cap-srv Node.js application
  • Bind all services to the application

6.6 Note the Deployed URL

cf app seasonal-detector-cap-srv

The routes line shows the URL, e.g.:

routes: seasonal-detector-cap-srv.cfapps.eu10.hana.ondemand.com

Record this URL — you will need it in the next step. Your two API base URLs will be:

VariableValue
CAP_TIMESERIES_URLhttps://seasonal-detector-cap-srv.cfapps.<region>.hana.ondemand.com/api/timeseries
CAP_CLASSIFICATIONS_URLhttps://seasonal-detector-cap-srv.cfapps.<region>.hana.ondemand.com/api/classifications

6.7 Verify CAP Backend Health

curl https://seasonal-detector-cap-srv.cfapps.<region>.hana.ondemand.com/health

Expected response: {"status":"UP"} or HTTP 200.

7. Configure & Deploy the Agent

7.1 Update Environment Variables in manifest.yml

Open assets/seasonal-article-detector-agent/manifest.yml and fill in the blank values:

env:
  CAP_TIMESERIES_URL:      "https://seasonal-detector-cap-srv.cfapps.<region>.hana.ondemand.com/api/timeseries"
  CAP_CLASSIFICATIONS_URL: "https://seasonal-detector-cap-srv.cfapps.<region>.hana.ondemand.com/api/classifications"
All other env vars have sensible defaults. Adjust thresholds only if required for your article/sales data characteristics.

7.2 Create Agent Service Instances (if not already done)

If you did not create these in Step 3.1, create them now:

cf create-service connectivity lite proj-vector-connectivity-service
cf create-service destination   lite proj-vector-destination-service

7.3 Deploy the Agent via Cloud Foundry Push

cd assets/seasonal-article-detector-agent
cf push

This uses manifest.yml in the current directory.

7.4 Deploy Workflows via Joule Studio (Optional — for AI Core runtime)

If you are deploying to Joule Studio instead of plain CF, trigger the GitHub Actions workflow. You must first configure the following secrets in your GitHub repository:

Secret NameWhere to find it
SCI_TENANT_URLJoule Studio tenant URL
SCI_CLIENT_IDJoule Studio service key → clientid
SCI_CLIENT_SECRETJoule Studio service key → clientsecret
JOULE_STUDIO_URLJoule Studio API URL

Then: GitHub → Actions → Deploy to Joule Studio → Run workflow.

9. Troubleshooting Guide

SymptomLikely CauseFix
BTP Destination Service binding not found The CF app is not bound to a Destination service instance Run cf bind-service <app> <destination-instance> then cf restart <app>
Destination 'CAR_HANA' not found (404) BTP Destination named CAR_HANA does not exist Create it in BTP Cockpit → Connectivity → Destinations (Section 3.3)
HANA connect failed: connection refused Cloud Connector is not running or not connected to this subaccount Check Cloud Connector Admin UI → Connector status is green; verify subaccount mapping
HANA connect failed: invalid credentials Wrong user/password in BTP Destination Edit BTP Destination → re-enter credentials → Check Connection
HANA SQL failed: insufficient privilege HANA user missing SELECT/INSERT grants Run GRANT statements from Section 5.2 as DBA
HANA SQL failed: invalid table name: ZSEASONAL_CLASS_RUN DDL script not executed yet Run ddl.sql against the HANA instance (Section 5.1)
Agent falls back to preview mock data CAP_TIMESERIES_URL or CAP_CLASSIFICATIONS_URL is blank Set both env vars in manifest.yml and re-push agent
CAP backend crashes on startup: Cannot find module 'socks-proxy-agent' npm install not run before deploy Run npm install inside assets/seasonal-detector-cap, then rebuild
BTP Connectivity Service binding not found CF app not bound to Connectivity service Run cf bind-service <app> <connectivity-instance> then cf restart
Cloud Connector shows destination as unreachable Firewall blocks TCP 30015 between Cloud Connector host and HANA Ask network team to open port 30015 from Cloud Connector host to HANA server
Connectivity token fetch failed: 401 XSUAA client credentials in Connectivity binding are wrong Delete and re-create the Connectivity service instance; rebind and restart
Wrong MANDT — no data returned from /DMF/TS_PS MANDT hardcoded as '100' but customer system uses different client Contact SAP to clarify: the MANDT filter is in timeseries-handler.js line with MANDT = '100' — update to the correct value and redeploy CAP
